Spec 001 · Unified web interface · demo evidence

Every page of the CivSim web interface, on fixture data

Spec 001 is a read-only FastAPI + Jinja service that sits over the match store on port 8420. Every route serves HTML to a browser and the same view model as JSON (?format=json or Accept: application/json). It reports and never acts: starting, pausing or branching a run is the harness's job, and the game client is never required.

What you are looking at

Every run, turn, step, event, yield and configuration on these pages is synthetic fixture data from tests/web_support/fixtures.py (make_store(), make_catalog_store(), make_event()). Nothing came from a real Civilization VI game: the run ids (run-live, run-01…run-05), the straight-line yields, the 2026-09-20T12:0x:00Z timestamps and the reasoning text are all fixture values.

The screen captures are real, but all the same frame. The fixtures' capture blobs are an 8-byte PNG signature (a broken image), so each screened-clean capture was swapped in-process for one genuine 720×450 window frame the 002 harness took of the Civ VI main menu. It does not correspond to the fixture turn it sits under.

Screenshots are viewport crops, not full-page captures: a page longer than the viewport is cut off at the bottom. That is the screenshot, not the page. The one real match store on this box was not used (see Not shown yet).

What the pass found

The README's pixel-level pass covered 01, 02, 04, 04b, 05b, 06, 06b, 07, 09, 10, 11, 12, 13, 13b, 15, 16, 17 and 18; files 03, 05, 08, 12b and 14 were checked only by HTTP status, content type and file size. These are the things it found wrong or misleading.

  1. "connection lost — this view may be stale" was shown on every load of the live view, even with the connection fine. FIXED A CSS bug, not a capture artefact. The template renders the marker with the hidden attribute and poll.js only un-hides it after two consecutive failed polls (the DOM after JS confirmed data-stale="false" and hidden="" still set). But style.css declared .stale-marker { display: block }, and an author display rule overrides the user-agent [hidden] { display: none }. So the warning text was visible on 04, 04b and 17 while the orange glance border that a genuine stale state adds was correctly absent. The fix has since landed in src/civsim_web/static/style.css as .stale-marker[hidden] { display: none } (commit 3616649). The screenshots above predate it.
  2. The live-view glance card overflows at phone width (17). .glance has fixed minimum grid columns (minmax(16rem,1fr) auto minmax(20rem,2fr) auto, at least ~36rem = 576px) and style.css has no @media rule at all, so at 420px the LAST DECISION and LAST CONFIRMED columns are clipped off the right edge. Everything below the card stacks fine.
  3. Duplicate "1" in the turn Jump list (05, 05b, 06, 06b: "Jump: 1 1 2 4 5 6 7 8"). turn_replay.html emits an unconditional link to turn 1, then its loop over range(max(turn-5,1), turn+6) emits turn 1 again whenever the current turn is 6 or lower. Cosmetic; both links work. On turn 7 (07) the list is correct.
  4. Placeholder rows on populated pages. The generic view-model renderer prints Empty state —, Listing limitation —, Active filters —, Requested but unrecorded —, Divergence points — and Unavailable fields — as literal rows even when there is nothing to say (01, 02, 04, 11, 12, 13). This is the UP-005 "absent is shown as absent" rule applied literally; it reads as noise on a page that has data. On the 404 page the first row is Error: error because the error view model literally carries "error": "error"; the informative field is "kind": "turn_gap", which the HTML page does not show as a row.
  5. /healthz serves JSON only. It answers application/json even to a browser asking for HTML, so 16 is Chromium's JSON viewer rather than a CivSim page. Deliberate (health is machine-facing), but worth knowing when you open it.
  6. Same real frame everywhere. Every capture slot shows the identical Civ VI main-menu frame. That is a limitation of this evidence set, not of the UI, which serves whatever bytes the store returns.
What looked right
  • Real PNG bytes served through /captures/{id}/image render as a proper image in the live view, the replay, the step page and the panel route.
  • The gap turn is refused with a 404 that explains itself (10); the metric charts break their line at the gap and mark it with a dashed red rule (05, 12b); the catalog and comparison quarantine gapped runs with a stated reason (02, 13); the superseded attempt stays reachable with a banner pointing at the authoritative one (07 vs 08). Principle III/IV reasoning is spelled out in prose on every page that applies it.
  • Every route also answers as JSON with the same field names the HTML shows, and the 404 is a structured JSON error, not an HTML-only page.
  • No external requests: Chromium talked only to 127.0.0.1:8420 (page, /static/style.css, /static/poll.js, capture images, and a harmless /favicon.ico 404). No webfonts, no CDN.
  • The dark theme, monospace values and left colour bars are consistent across all pages; nothing rendered with missing styles.

Not exercised in this pass: the step-scoped panel route, ?page= on the catalog, ?series= on metrics, &metrics= on compare, the withheld-capture rendering (turn 5 exists in the fixture but was not screenshotted), the published_port_only store shape, and an unreachable store (the 503 path).

Not shown yet: real-run pages

The one real MatchStore on this box (civsim-match-store.db at the repo root) was not used for these shots. It was in use by a live harness run while they were taken, and it currently holds only paused runs from tonight's live harness attempts: a few-run, few-turn store that would not exercise the catalog, comparison, replay-attempt or gap pages at all.

Real-run screenshots follow once a run finishes. Wiring the real store in is a --store module:attr change on the launcher, nothing in the UI.

Reproduce with the shipped CLI (fixture store, no real frames, no merged catalog), then open http://127.0.0.1:8420/:

PYTHONPATH=/home/matt/CivSolver .venv/bin/civsim-web \
  --store tests.web_support.fixtures:make_store --bind 127.0.0.1 serve

Full details, including the in-process launcher that merged the catalog fixtures and substituted the real frame, are in this folder's README.md.
