## The pattern this pass found, and it is the report's headline

Three audits ran in parallel against different surfaces — requirement coverage derived from code
and tests, the five findings from last night's live play, and cross-artifact consistency. They
were not looking for the same thing. They returned the same thing.

> **The unreached mechanism.** A mechanism that exists, is well built, is covered by passing
> tests, and is never reached in the case it was written for — with the suite green throughout.

Six independent instances, found in one day:

1. **The content screening gate cannot detect the FireTuner window, in production, on any
   platform.** Its declared-text technique fires only when `tokens <= detected_text_tokens`, and
   `detected_text_tokens` defaults to `frozenset()` with **no production caller anywhere in
   `src/` supplying it**. Five of six Linux reject categories — including `firetuner_window`
   itself — are structurally undetectable. The two tests that look like coverage inject the one
   input production cannot produce.
2. **The source gate's process-identity check is unwired**, same call site, same shape — and
   `test_source_gate_skips_process_check_when_none_supplied` asserts the clean result for
   *exactly the production shape*, encoding the gap as intended behaviour.
3. **A correct prompt-key helper had zero callers in `src/`** while a naive prefix-swap
   reimplementation sat in the call path. It was right for twelve of thirteen prompt
   declarations and wrong for the thirteenth; the cost was total, because an unanswerable prompt
   keeps `has_blocking_prompt` true and no run on that board can advance a turn at all.
4. **The catalog's bespoke-path validator only fires on `path: bespoke`**, so a bespoke path
   mislabelled `firetuner` passes vacuously. It validates the declaration against itself.
5. **The orphan sweep cannot reach an orphan.** `scan_orphans`, the open-time write-mode sweep and
   `civsim store repair` all start from a run **row** and ask about its lock. None starts from a
   **lock** and asks whether it has a run — so a lock whose run never reached a store is outside
   the machinery entirely and silently blocks the next run.
6. **FR-011's "never applied without verification" has no check of any kind.** It holds today by
   construction across 619 recorded decisions; nothing observes that it keeps holding.

A seventh instance is the cleanest of all, because there the false claim is written down two
paragraphs above the code that contradicts it:
`test_write_then_advance_calls_end_turn_only_after_a_durable_write` passes a **fake** `end_turn`
callable and proves the guard orders *its own* callable after the write — true, and blind, because
the real `Game.EndTurn()` dispatch for the two commonest outcomes never goes through the guard at
all. The test and the guard share the assumption that the guard is the only route to ending a
turn, which is exactly what `guard.py:26-34` asserts and the run loop does not honour (D2).

In every case the guard is *well built*, and that is exactly why the hole is invisible: nothing is
red. This is a sharper statement of what previous passes called "a check written from the same
mental model as the code" — the failure is not that the check is narrow, it is that the mechanism
is never entered. The countermeasure that would have caught all seven is the same one 001's T078
demonstrated: **assert the thing that should not happen, not only the thing that should**, and
require a negative control to prove the assertion can fire.

D1 shows the shape at its most layered. A check that loads the declared YAML, counts zero
`path: bespoke` entries and confirms every `firetuner_gap` is null is *literally true* and
*entirely blind*, because the mislabel is upstream of the field being read. `plan.md:300-301`
cites that check as proof, `validation-results.md:34` records it as evidence, and the load-time
validator fires only on `path: bespoke` — **three layers, one blind spot, because all three read
the same field.** The lesson generalises: a verification that reads the same declaration the code
reads is not independent of it.

### The second pattern: a value whose name asserts something the value does not mean

Distinct enough from the first to name separately, with three instances of its own:

- **`turn_reached: N`** counts the **harness's own turn cycles from 1**, not the game's turn
  number. It is already in this project's gotcha list, and it still bit twice today — the second
  time an agent read `turn_reached@1` firing as proof that a real game turn had been played on the
  live client and published that inference to the coordination board, where it had to be chased
  and corrected.
- **`dispatch_result`** `{"ok": true}` means **the call returned**, not that it took effect. The
  field's own semantics stand; it is recorded, never authoritative, and `outcome` still derives
  from the verification predicate.
  **Retraction, recorded rather than quietly deleted**: this was originally evidenced by
  `UI.SetMapZoom(0.5, …)` returning cleanly while `UI.GetMapZoom()` read `0.0499997`, and by
  `DiplomacyManager.CloseSession()` reporting `ok: true` while appearing to do nothing. **Both are
  withdrawn — neither was a no-op.** The tuner returns the **pre-call value when the readback is
  issued inside the same command as the write**: the same zoom read back `0.0499997` in-command and
  `0.50000047683716` in a later one. Both calls worked; the measurement was wrong.
- **`shown_to_agent`** records an **intention**, not an outcome — it is written before
  `provider.complete()` returns, while its own docstring claims it "reports what happened, never
  an intention". Thirteen live rows prove the gap (C5).

The countermeasure differs from the first pattern's. A fact that must be *remembered* in order to
avoid a wrong conclusion will keep producing wrong conclusions — the gotcha list is precisely
where `turn_reached` already lived while failing twice. **The fix is to make the wrong reading
impossible, not better documented**: rename the field to name the harness cycle explicitly, or
give it a type that cannot be compared against a game turn.

### The third pattern: measuring through a channel that reports the state before the change

> **A readback issued in the same tuner command as the write is not a readback.**

The tuner returns the **pre-call value** when the read is inlined with the write. Every
verification in the harness shaped that way is suspect, and it has already corrupted the record:
`turn.end_turn` now dispatches correctly after the prompt fix, but the harness re-reads the turn
number before the asynchronous advance lands, so **three turn cycles recorded
`game_turn_advanced: False` while the game demonstrably advanced from 56 to 57. The harness caused
three turns and credited itself with none.** That is a **Principle III** defect — the turn-by-turn
record denies an event it caused — and by the store's own rule a run with gaps cannot feed
trending (T293).

**The subtle and important half: the architecture already does the right thing where it re-reads
separately.** `cities.set_production`'s success verdict came from the harness's **later
re-observation**, not from the Lua's same-command answer, which said `confirmed: false`. The defect
is confined to the places that read back inline — which is why it is a pattern to hunt rather than
a design flaw to redesign.

Three parties hit this class today in different forms — two lanes and the hypervisor — each
measuring through a channel that reported the state before the change.

### The fail-safe corollary — the best predictor of where the next finding lives

> **A fail-safe defect survives longest in exactly the mechanisms we trust most**, because a guard
> erring toward "not ready" or "withhold" never produces a visible incident. **So audit the
> fail-safe direction deliberately, because nothing else will make you.**

Three of this pass's findings share it, and **not one announced itself**:

| defect | errs toward | why nobody noticed |
|---|---|---|
| `firetuner_window` unmatchable (T299) | withhold nothing, *guard reports the category addressed* | no frame is wrongly withheld, so no incident |
| the suite gate's `pytest` matcher | report busy on a clear box | waiting looks like caution |
| completeness exempting the in-flight turn (T298) | report `complete` for a run that lost data | nothing is red, and the run looks healthy |

**Every one of these sat all day while the dangerous defects were found in minutes** — precisely
because they were the checks we trusted. That is a better predictor of where the next serious
finding lives than any defect taxonomy in this report.

### Gate on what the measurement is for

The day's green — **2311 passed / 19 skipped / 41 deselected / 0 failed, 248.84 s, at `96dabb6`**,
in a dedicated worktree at a pinned head with `uv sync --all-groups --all-extras`, a bare
`uv run`, **ungated**, and isolation proven *before* the run (`civsim_harness` resolving into the
checkpoint worktree) — settled a question this pass had been arguing from both sides.

**A functional result is not load-sensitive; a timing result is, and cannot be rescued by waiting.**
248 s on a loaded box against ~225 s quiet is ~10% — noise for a pass/fail assertion, and
meaningless against the 3.4× spread measured on the `/compare` case. So the rule is not "wait for
quiet" and not "gate less": **gate on the property being established.** Functional runs need
isolation and a pinned head. Timing runs need a quiet box *and* enough samples to reach the tail —
and on this machine the first was never going to arrive, since the game client is its normal
working state. **That retires the last defence of the render budget as a wall-clock assertion**
(T282).

### Two failures at two altitudes, both cheap to fix

- **A claim nobody re-checks.** A relay carrying authority is the least-audited statement in the
  system: three times this pass a subagent's claim was passed on as established and two of those
  were false.
- **An answer nobody looks up.** The correct `pytest` matcher (`grep -c "[b]in/pytest"`) **already
  existed in the tree** while two lanes independently used a form that also matched monitoring
  scripts and their own command lines.

Neither is fixed by being more careful. Both are fixed by a lookup: re-check the claim, or grep for
the answer that is already there.

### The instances this pass produced in its own tooling

Recorded because they are the most useful examples in the set, not the least:

- **A verification rule that did not verify.** "Run the suite in a clean detached worktree" was
  adopted as a standing rule and, as first written, silently read the **shared tree** anyway,
  because the venv's editable install resolves the package to `/home/matt/CivSolver/src`. A
  mechanism that exists, looks right, carries authority, and does not reach what it claims to
  verify — introduced *as the fix for this very pattern*.
- **Its correction was also wrong, twice.** The first correction (pin `PYTHONPATH` onto the
  borrowed venv) was broadcast on the strength of an undiagnosed error message; the second
  (a bare `uv run` in the worktree) **builds a fresh, incomplete environment** — measured here:
  `ModuleNotFoundError: No module named 'jinja2'`, **2 collection errors, 11 skipped, 0 tests
  actually run**. A rule that produces a near-empty run reads as "verified" to anyone skimming.
- **What actually works, measured rather than reasoned:** from the worktree, with the real venv
  borrowed *and* the worktree's `src` pinned, `civsim_harness.__file__` resolves to
  `/home/matt/CivSolver-verify/src/...` **and** every dependency is present —
  **2178 passed / 20 skipped / 0 failed in 250.28 s** at `2fd3d11`. The decisive check is not which
  invocation form is used but whether `civsim_harness.__file__` points into the worktree; that is
  one command and it settles it. **Verify the verifier, every time.**

## The practice that overturned this pass's wrong answers

The three most confident wrong statements made during this pass were each overturned by going to
the primary artifact rather than reasoning about it:

| Claim | Overturned by |
|---|---|
| "No frame has yet been shown to the agent on any platform" | Reading the store rows: **300 captures `shown_to_agent=True`, 287 model calls carrying an image** |
| "The headless lane took the stale run lock" | Reading the lock file's own bytes: `client_pid 2459457`, which was the other lane's own Stage 1 launch |
| "This structural check would have caught the gate defect" | Implementing and running it — three formulations, **C0 and C0b absent from all three** |

**Rule, recorded as practice rather than anecdote: when a claim is load-bearing, read the artifact
instead of reasoning about it, because the reasoning is usually the thing that is wrong.** A
corollary learned the same day: in a tree several agents are editing, anything asserted about
*committed* state must be checked with `git show HEAD:<file>`, with `git status` consulted before
concluding a file is clean — a plain read shows another agent's half-finished work.
