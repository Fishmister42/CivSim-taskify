# lua/ACCESSORS.txt -- every Civilization VI accessor lua/**/*.lua is allowed to name.
#
# WHY THIS FILE EXISTS
# On 2026-09-21 the same defect was found three times in one day: a body calling a method
# Civilization VI does not have, behind an `if obj.Method then` guard or a `pcall` that swallowed
# the absence, so the harness reported an honest-looking empty value for hundreds of steps and the
# dependent action could never become available. `cities.set_production` was dead for 399 steps on
# `buildQueue:GetAvailableProduction()`; `units.promote` was dead on
# `unit:GetAvailablePromotions()`. The full audit
# (specs/002-civ-playing-harness/spikes/lua-accessor-audit-2026-09-21.md) found 28 such names
# across 38 call sites. An empty list is a value, so no "does the body answer?" test can catch
# this. Only "does this name exist?" can, and that is what this file plus
# tests/unit/test_lua_accessors.py do.
#
# THE CONTRACT
# tests/unit/test_lua_accessors.py extracts every `obj:Method(` and every `Global.Name` from
# lua/**/*.lua and asserts the set equals this file's, IN BOTH DIRECTIONS:
#   * a name in the Lua that is not listed here fails -- the phantom guard;
#   * a name listed here that no longer appears in the Lua fails -- so the list cannot rot into a
#     blanket permission slip.
# Adding a genuinely new accessor is a two-line change: the call, and its citation here.
#
# THE CITATIONS
# Each line is `<name>  <file:line>`, where file:line is relative to
#   <Civ VI install>/steamassets/
# and is a place Firaxis' own shipped Lua uses that exact name. Every entry below was generated by
# searching the installed game (645 .lua files under steamassets/: base/assets/ui, base/assets/maps,
# dlc/*/ui, dlc/*/scripts, ctp, debug, launchpad) -- no name is listed without one. The citation is
# the FIRST use found in a stable preference order (unit/screen/popup/chooser panels before other
# base UI, base before dlc); it is a proof of existence and a place to read the calling convention,
# not the only caller.
#
# CORROBORATION, and why it is only corroboration. Three binary oracles were used to confirm the
# negatives (the 28 names the audit removed) and to check every replacement:
#   * the Lua binding symbols in Civ6 / libGameCore_{Base,XP1,XP2}.so
#     (GameCore::...::Lua::I<Interface>::l<Method>), and
#   * the shipped Windows linker maps
#     steamassets/dlc/expansion{1,2}/binaries/win64/gamecore_xp{1,2}_finalrelease.map, in which
#     every Lua-callable method appears as a trampoline
#     ?l<Name>@I<Interface>@Lua@Cache@GameCore@@KAHPEAUlua_State@@@Z. A trampoline is not evidence
#     about the API, it IS the registration, and it names the interface the method is bound on.
# Presence of a trampoline is conclusive. ABSENCE IS NOT: pPlayer:GetFavor()
# (toppanel_expansion2.lua:169), culture:CanPolicyBeSlotted and culture:IsPolicyBanned
# (governmentscreen_expansion2.lua:9-10) are all called by Firaxis' own shipped Lua and have no
# trampoline symbol in any of them, most likely identical-code folding. That is why the usage
# citation below is the primary basis for every entry and the binaries only corroborate it. The
# reverse also holds: culture:CanChangeGovernment has a trampoline but no caller, so a name being
# unused is not a name being invented.
#
# CI has no Civilization VI install, which is why the citations are checked in rather than
# re-derived. The full extraction method is in the audit spike.
#
# WHAT THIS FILE DOES NOT PROVE
# That a name exists is not that it answers in the tuner context a declaration is assigned to, is
# bound on the object the harness calls it on, or takes the arguments the harness passes. Findings
# 17, 21, 29 and 30 in the audit are all real names used wrongly. Read the caller.
