{# Shared rendering macros (T030). These exist to make one property true by construction rather than by diligence: **every field in a response's JSON body is present in its rendered HTML, and no field is present in the HTML that the JSON lacks** (contracts/web-read-api.md, FR-007, UP-002). `node` walks the view model's own serialized form -- the same `data` the JSON body is built from -- and emits one `data-field=""` element per leaf. The paths are exactly the JSON paths, which is what lets `tests/contract/test_web_read_api.py` assert parity mechanically instead of by a per-field checklist, and what lets `static/poll.js` update the page in place without knowing anything about the schema. The consequence worth stating for later stories: **a field added to a view model appears on the page with no template change.** Add fields to the models; add bespoke markup here only when a value needs more than a label and a value (an image, a link, an expandable block). Every macro takes `path`, the dotted JSON path of the value it is rendering.
